# Changelog

## Unreleased

- Audit run 9's hunters' notes.
  - Microphone sleep is timed on the continuous clock, so setting the clock back cannot keep a hands-free microphone awake, and time the Mac spent asleep counts as quiet.
  - A session hung in "working" no longer keeps the microphone awake for ever: phases that stay unchanged count as conversation for at most 20 minutes. A conversation that keeps moving is not affected.
  - PairVox's own prompt or notice heard back, when it is not an answer, is dropped instead of being sent to Claude. While a request waited, such an echo used to deny it as "no, do this instead".
  - Install Latest Build… runs the installer with an allow-list of variables (PATH, HOME, locale, Xcode, the SSH agent, proxies and the signing choices) instead of the Claude child's deny-list, which passed tokens such as `GITHUB_TOKEN`.
  - `scripts/pv-install.sh --rollback` refuses a previous copy with a broken signature or a different signing team from the installed app, as an install already did.
- The Mac now checks the timing of a spoken answer from the iPhone itself instead of relying only on the phone. A spoken yes that reaches the Mac less than 1.5 s after the card first went out to the phone was begun before the phone asked, and the phone says "I heard that before the phone asked. Please answer again." A spoken no is not held back.
- A tap on Allow on the iPhone stops counting for a request that has waited more than 30 minutes; approve it on the Mac. A spoken yes and the lock-screen Allow keep their five-minute limit (backlog 3.3).
- A spoken question that is over before it played is no longer asked afterwards. Until now this held only when a request was answered. Now it also holds when Claude Code cancels the request, Claude Code exits, the turn ends with a request still open, a new session starts, a request replaces the folder-access offer, or the offer is answered, cancelled or put off on screen. A question already playing is left to finish (audit run 9's deferred prompt-queue unit).
- The iPhone app no longer crashes when it starts listening after the audio device changed. A Bluetooth headset switching to its 16 kHz call mode left the microphone engine reporting 48 kHz, and a tap in that format raised an exception the app could not catch (seen in the Simulator on 2026-10-25). The same crash happened when listening started before anything had played, because the audio session could not record yet. The phone now sets the session up for recording first, uses a new engine for every listen, taps in the format the hardware runs at, and reports a microphone that is not ready instead of crashing.
- When speech recognition fails as soon as it starts (the Simulator, or a phone without its on-device speech model), hands-free listening no longer restarts four times a second. After three quick failures in a row the phone mutes and says recognition is not working. Tap the microphone to try again.

## 0.1.0-beta.2 (2026-10-25)

Release notes: docs/release-notes/v0.1.0-beta.2.md. Security: docs/security/2026-10-25-audit-run-9/ and docs/security/strix/2026-10-25-beta2-gate.md.

- Audit run 9 (docs/security/2026-10-25-audit-run-9/).
  - The downloaded Mac app can no longer be debugged by other programs. The 0.1.0-beta.1 DMG carried `get-task-allow` and no hardened runtime, so any process of the same user could attach to it. Ad-hoc builds are now re-signed with the hardened runtime and explicit entitlements, and `scripts/release.sh --dry-run` fails on either problem. Replace a beta.1 install with this build.
  - Each spoken answer is timed by its own start. The start used to be one shared value, so a second utterance or a short blip could leave a "yes" untimed, and an untimed answer skipped the before-the-question and own-voice checks. Typed text is now marked as typed.
  - A second "allow all" counts only after the list it confirms has started playing, and it allows only requests that are still fresh.
  - `nice env`, `timeout 5 env` and other wrapped `env` commands, and `ps` with the e flag anywhere (`ps -ax -E`, `nice ps eww`), are high risk, so a folder shell grant never covers them.
  - The lock-screen Allow button appears only for a request that fits on one plain line, with no line breaks or direction-override characters. The Mac checks lock-screen answers the same way.
  - Muting clears the short lead-in buffer and stops it filling, so push-to-talk after a mute sends nothing heard while muted. A sleeping microphone records when you hold the push-to-talk key, and stops when you let go.
  - `scripts/release-assets.sh` refuses uncommitted changes (`--allow-dirty` to test) and takes `--strix-run DIR`.
- The hands-free microphone goes to sleep after 3 minutes without conversation. Asleep, it is muted, the top bar turns orange and shows "Microphone asleep · Wake", and the microphone icon becomes a moon. Click Wake or press the mute shortcut (⌃⌥M anywhere) to turn it back on. A sleeping microphone records when you hold the push-to-talk key, and stops when you let go. Claude thinking, working or speaking in any project counts as conversation, and so does anything you send. Sound that never became a message does not, and it never sleeps while you are talking. Settings, General, Listening sets the time (3, 5, 10 or 30 minutes) or turns it off.
- `scripts/release-assets.sh VERSION` builds every file a release carries into one folder: the Mac DMG, the unsigned iPhone `.ipa`, the newest Strix report, a zip of the security reports and `SHA256SUMS`. It accepts `--out`, `--signed` (signed and notarized through `scripts/release.sh`), `--dry-run` and `--json`, never touches `dist/`, never uploads, and prints the `gh release create` line to run.
- `pairvox-link-testhost` answers an approval or denial with a reply, so a phone run shows the whole loop.
- Folder access is no longer granted by voice by default. A spoken or typed yes to the "allow Claude to edit all files inside it" offer, or to the shell-commands offer, gets "Folder access needs a click", and the question now ends "Answer on screen, or say no." A spoken no still declines. With "Allow confirming high-risk requests by voice" on, "yes" then "confirm" still grant it, but each must be begun after that step's question started playing, must not be PairVox's own words heard back, and must come within five minutes of the question. With Touch ID or password confirmation on, a spoken grant asks for that too. The buttons work as before. On 2026-10-25 a hands-free session in a room where people were talking ended with a grant for the demo folder.

## 0.1.0-beta.1 (2026-10-25)

First public pre-release: the Mac app (ad-hoc signed DMG, not notarized) and the iPhone app (unsigned .ipa). Release notes: docs/release-notes/v0.1.0-beta.1.md.

- Easier to use.
  - When a spoken answer does not count, the request card says so and why: you started before the question played, it sounded like PairVox's own voice, the request waited too long, or it needs "confirm high risk" or a click. When you spoke before the question, PairVox says "I heard that before I asked" and asks again.
  - A health indicator at the end of the toolbar reads Ready (green), Limited (orange) or Not working (red), with a different shape for each. Click it for every part: microphone, audio, Claude Code, speech recognition, voice, echo cancellation and the phone link (counted only when it is on). Each part that needs attention says what is wrong and has one fix button: Allow…, Open Privacy Settings, Restart Audio, Sign In in Terminal, Try Again, Download, Turn On, Pair a Phone… The same list is in Settings, Health.
  - One-click update for a build from this checkout. PairVox, Install Latest Build… brings the branch up to date, builds it while you keep working, keeps the current app as `dist/PairVox.previous.app`, then quits and reopens with the new one. `scripts/pv-install.sh` does the same from the command line (`--pull`, `--dry-run`, `--json`, `--rollback`), and the menu run's output is in `~/Library/Logs/PairVox/update.log`.
- Pre-release security pass and audit run 8 (docs/security/2026-10-25-audit-run-8/).
  - The lock-screen Allow button appears only for a request the notification shows in full (160 characters or less) and the Mac allows by voice. A long, high-risk or screen-only request opens the app instead. The Mac checks a lock-screen answer against the same rule and the five-minute limit, and forgetting the Mac clears delivered notifications.
  - The note PairVox says when it thinks it heard its own voice now reads "That sounded like my own voice. If it was you, answer again." The old note ended in "say yes" and could be heard back as a yes. Heard-back notices and announcements are ignored like heard-back prompts, for every kind of spoken approval, and also for an approval to another project's request.
  - Only the question for the request now waiting opens its answer window. A question left over from a request already answered is dropped from the queue.
  - A command given to a shell with `-c` (`sh -c 'env'`, `bash -lc printenv`) is rated as the command inside it. `ps` with the e flag, which prints other processes' environments, is high risk.
  - The one-click installer runs with the same filtered environment as Claude Code and refuses to replace a team-signed app with a build that has no team. `restart-app.sh` looks only at your own processes.
  - Strix on current `main` found nothing, and a Gitleaks scan of the full history found no secrets (`.gitleaks.toml` allows the session fixture's message IDs).
- Stability and audit run 7 (docs/security/2026-10-24-audit-run-7/).
  - The voice warms up when you start talking after a quiet spell, so the first sentence of the reply is not slow (on 2026-10-18 it took 5.0 s). Kokoro renders one throwaway word on the voice queue if it has been idle for 20 s, and `kokoro.warmUp` in the log gives its time.
  - Claude's output is read in time proportional to its size. The line reader scans each byte once and drops an over-long line whole, including its tail. JSON nested deeper than 100 levels is refused before decoding. The speech parser no longer copies an undecided line for every character.
  - PairVox no longer hears itself say "Allow". Echo handling stays on for half a second after playback, and a spoken approval made of the prompt's own words, said while it plays or just after, does not count. The phone waits a little longer after speaking before it listens, and ignores its own words the same way.
  - A dangling symlink in the project is judged where a write through it would land. NotebookEdit is judged by every path it names. A WebFetch address with a backslash, `@`, user info or spaces is approved on screen only.
  - "Always allow" adds only allow rules for this session. A mode change such as `acceptEdits`, or an added folder, is no longer applied, and the button is hidden when nothing narrow is left.
  - Repository names that contain answer words are kept out of the speech recognizer's vocabulary.
  - On the iPhone, a request that arrives while PairVox is in the background (during the grace iOS allows after you leave the app, or while it plays the Mac's voice) shows a lock-screen notification. An ordinary request has Allow and Deny buttons, which ask for Face ID or the passcode first. A high-risk one opens the app. A high-risk tap from a phone with no passcode is refused, on the phone and on the Mac.
  - The "Sign in with Terminal" button works when the path to `claude` contains a space.
- Approval gate fixes from security audit run 6 (docs/security/2026-10-24-audit-run-6/). A question that contains an approving word ("Is that okay?", "Should I allow it") is no longer taken as a yes, on the Mac or from the phone; it goes to the advisor. A spoken yes counts only if you began saying it after the request's prompt started playing, so "sounds good" said to Claude's previous sentence cannot approve a request you have not heard; typed answers and clicks are unchanged. Wrapped or piped deletes (`ls | xargs rm -rf`, `timeout 60 rm --recursive`, `env -i rm …`, `sh -c '…'`) and quote-split `git push` are high risk, because wrappers are skipped with their options before the program is judged. Printing the environment (`printenv`, bare `env`, `export -p`, any mention of `ANTHROPIC_API_KEY`) is high risk and never covered by a folder grant. `~/.CLAUDE` and other re-cased spellings of protected folders rate as high as the usual spelling. The card for an MCP or other unrecognised tool lists the arguments it will be sent, and MCP tools are approved on screen only. On the phone, the pairing host must be a parsed Tailscale address or a `.ts.net` name; `fd7a:115c:a1e0:x.example.com` and leading-zero octets are refused.
- The iPhone speaks with the Mac's own voice. Each sentence is sent to the phone as AAC audio when it starts playing on the Mac (about 9.5 KB per second of speech), and the phone plays it in order, so replies sound the same on both devices instead of the iPhone's text-to-speech. When the Mac stops speaking (you talked over it, or the turn was interrupted) the phone stops too. Text-to-speech on the phone remains for its own request prompts and for anything without audio. The Mac and phone apps must be updated together.
- A turn that finished as Claude Code exited no longer reads as a crash. The exit used to be reported while its last lines, often the turn's result, were still unread. Both output streams are now read to the end first, for up to two seconds.
- Typing or pasting a long message can no longer freeze a session. A write to Claude Code's input held the session lock, which the output reader needs, so a child that was not reading its input stopped all output and the Stop command. Writes now run in order on their own queue, outside the lock.
- PairVox no longer hangs at launch when a shell startup file leaves a background process running. Reading the login shell waited for that process to close its output, with no time limit. It now waits at most one second after the shell exits.
- The phone link listens only on the Mac's Tailscale address, or on 127.0.0.1 when Tailscale runs in userspace mode. It used to accept connections on every interface. A 100.64.x.x address counts as Tailscale only on a Tailscale tunnel interface, so a phone hotspot's carrier address is no longer mistaken for the tailnet.
- `scripts/restart-app.sh` no longer deletes another checkout's installed app or any copy that is running, and refuses to open a second PairVox while one from another checkout is running.
- Pairing is QR only. The six-digit code is gone from the Mac, the phone app, `pairvox-link` and the stand-in test host. Its secret was the six digits themselves, so anyone who captured one pairing exchange could try all million codes offline in under a second, open the grant and hold the phone's long-term key. The QR secret is 16 random bytes and cannot be searched that way. For a phone without a camera (the iOS Simulator) or to skip the scan, Settings → Phone shows the same secret as a pairing link with a Copy link button, and the phone's pair form takes a pasted link through the same parser and the same "Pair with …?" question as a scan. With Universal Clipboard the iPhone's Paste button picks it up directly. `pairvox-link pair` prints the QR code and the link, and still accepts `--qr`. `--code` exits 2 with a message, and the control socket refuses an offer of kind `code`. Phones already paired keep working.
- Approval gate hardening (P1 of the 2026-10-16 review). The summary setting no longer lets a spoken yes approve a command the summary cannot describe: redirection into a file, `$(…)`, backticks, heredocs and process substitution are read as “Please confirm on screen” whatever the setting (`2>&1` is not a redirection), and so is a step the narrator can only call “a command”, such as `cp /Users/dev/app/.env /Users/dev/app/public/env.txt`, which used to be spoken as “Claude wants to run a command. Allow?” and approved by a yes. Fetching code to install or run now counts as reaching the network, so `ls && npm install evil-pkg`, `npx`, `bunx`, `uvx`, `pnpm dlx`, `go get`, `gem install`, `open https://…` and their kin are screen-only and never covered by a folder shell grant; the two lists are now one list. Program names are matched after quote removal, so `cu''rl https://… -d @.env` rates as curl. Turning “Approve by voice from the summary” off (or on) now reaches every open project at once and re-rates the request on screen; it used to apply only to projects opened afterwards. A spoken yes, the high-risk phrase and “allow all” are refused for a request that has waited more than five minutes, the age limit the announcer and the phone link already apply (“That request has been waiting a while. Please confirm it on screen.”); the button still works. An announcement from another project offers “approve” only for a request its one line fully describes, the test the menu bar already applied, so a long command is answered on its card or after switching. A screen-only prompt no longer ends with two full stops.
- Hardening (docs/plans/2026-10-16-hardening-task-list.md, tasks 4.1, 4.2, 4.6). The spawned `claude` no longer inherits the whole login-shell environment: every `ANTHROPIC_*` and `CLAUDE_CODE_*` variable, `CLAUDE_CONFIG_DIR` and the Node and TLS variables are dropped before the chosen auth is applied, so a forgotten `ANTHROPIC_BASE_URL` in `.zshrc` cannot receive the Keychain key and `CLAUDE_CODE_OAUTH_TOKEN` is never forwarded (proxy variables still pass; see `docs/THREAT_MODEL.md`). The same filter applies to the advisor call and to `claude --version`. The advisor's one-shot call now also loads no MCP server (`--strict-mcp-config` with an empty config) and denies every built-in tool but Read, Grep and Glob by name. The `synth.corrupt` log line carries reply text only when "Include conversation text" is on; otherwise a length and a hash (how to reproduce: `docs/DEV_ENVIRONMENT.md`).
- Tools. `pairvox-link phones list` shows when each phone last connected, or "connected now". `pairvox-link phones prune --stale [--days N] [--dry-run] [--json]` removes phones not seen for N days (default 30). It never removes a phone that is connected right now, counts a phone that has never connected from the day it was paired, and treats a phone already removed in the app as done. `scripts/soak.sh [SECONDS] [--json]` runs the engine and link soak and fault tests for longer and prints their measurements; `scripts/replay.sh [--explore] [TEST-NAME-REGEX]` runs the voice replay scenarios. Both exit non-zero when a test fails, when `swift test` fails, or when no test ran. `scripts/release.sh VERSION --dry-run` builds ad-hoc into `.build/release-dry` and checks the bundle; any other second argument is an error, so a typo cannot start a real release. A real release stamps `CFBundleVersion` with the commit count and stops if the app carries `get-task-allow`.
- Launches that looked hung were a permission dialog. Every local build was ad-hoc signed, so macOS saw each rebuild as a new app and asked for the microphone again, and the app waited in that dialog before it registered its shortcuts, reopened the projects, started playback or answered the phone (measured: 31 seconds in one launch, three hours in another). `scripts/build-app.sh` now signs with the Mac's Apple Development certificate when there is one, so the grant is kept across rebuilds (the next rebuild registered its shortcuts at 1.2 seconds with no dialog), and the launch no longer waits for a microphone answer at all: playback, shortcuts, projects and the phone link come up first and the microphone is asked for after. A development build keeps its phone keys in the key file whichever certificate signed it; only a distribution signature moves them to the Keychain (the first certificate-signed build had looked in the Keychain, found no key for the paired phone and told it "revoked"). An audio engine that fails to start now writes the error to the log (`engine.start.failed`); it used to show a banner only. `scripts/launch-check.sh` reads the newest launch and fails when the shortcuts came late or the engine did not start.
- Requests are read as one line you can act on, and a spoken yes answers it. "Claude wants to edit ControlBarView dot swift in the project folder. Allow?"; "Claude wants to run swift test and 3 more steps shown on screen. Allow?". A long command used to be read out in full (up to 28 seconds of paths and flags), and a spoken "approve" was refused for it because the readout could not stand for the whole command, so the card stayed. New setting under Permissions, on by default: "Approve by voice from the summary, without hearing the full command"; the full command is always on the card. Off, a command too long to read in full needs a click, as before. High-risk requests and commands that reach the network are unchanged.
- Screech in replies, measured and the first fixes. The log showed Kokoro returning bursts of garbage (sample values up to 10³³) inside otherwise normal sentences of 104 characters and more; the same sentence came out bad again on retry and clean once split in two. Headless, the voice also renders the same sentence differently from one call to the next: the first render is about 4 dB louder with 60% more energy above 9 kHz than a repeat, and across a session sentence peaks ranged from 0.26 to 0.92. Changes: sentences over 110 characters are synthesized in clause-sized pieces and joined (their own silence trimmed, so the join sounds like a comma); every sentence is brought to one level before it plays (gain from the loud part of the sentence, bounded, peak capped); when the output device runs below 24 kHz (a Bluetooth headset in call mode runs at 16 kHz) the sentence is converted to the device's rate with the best converter before it is scheduled, so what the headset cannot carry is filtered out instead of folded back as noise by the mixer; a corrupt sentence is identified in the log (its length and a SHA-256 prefix; the text itself only when "Include conversation text" is on) so the fault can be reproduced with `--tts-probe`; and the app's stderr goes to `~/Library/Logs/PairVox/stderr.log`, where MLX and Metal report their failures. A spectral noise check was built and calibrated on the real voice, then kept as a logged metric only: a loud sibilant has the same spectrum as noise.
- An engine restart while speech was playing could lock up the audio engine for good: the output tap asked the player node whether it was playing, which needs the engine lock that the stopping side holds while it waits for that same tap to return. Seen as a hung test run; in the app the same race ran on every headset change. The tap now reads a flag kept by the code that starts and stops the player, and a watchdog test stops the engine under a running tap forty times.
- Playback recording keeps every engine start: a headset arriving or leaving restarts the engine, and the restart used to reopen the same `playback-<run>.caf` and erase what came before, which is the part a device problem is heard in. Segments are now `playback-<run>.caf`, `playback-<run>-2.caf` and so on.
- Fixes found by auditing the phone link. The reconnect loop no longer loses a nudge that arrives while an attempt is in flight (the attempt is cut short and the next one starts at once), no longer lets a replaced loop clear the new loop's session, and releases a stuck connect when the loop is cancelled. A Mac with no project open now sends an idle heartbeat, so a phone's own silence timer no longer drops a healthy link every 35 seconds. The phone waits 25 seconds, not 15, before it takes a link for dead on returning to the front, because a healthy idle Mac can be silent for 15. On the phone, a request left over from before a drop cannot be approved until the Mac has confirmed what is waiting, other-project requests are disabled while offline, a Face ID result is checked against the request again before anything is sent, only one pairing can run at a time, the paired state no longer flips to the pairing form when the phone is launched while locked, and the first network report no longer causes a reconnect.
- Phone app polish:
    - The Pair form includes a "Done" key above the number pad, a "Pair" button in the title bar (the keypad used to hide the one in the form), and clear buttons for every field.
    - The pairing code is limited to six digits.
    - The footer identifies the source of the address.
    - Connection failures use plain language (e.g., "Your Mac is reachable but nothing answers on port 47821. Is PairVox open with the phone link switched on?" or "No path to your Mac. Check that Tailscale is on…") and display the framework's specific error under "Details." These messages remain on screen during retries rather than flashing.
    - The status bar displays human-readable states ("Waiting for you", "Working", "Ready") accompanied by a colored dot, replacing the engine's internal phase names.
    - If a link is dropped, the remaining request card is dimmed and its buttons are disabled until the Mac reconnects.
    - New requests trigger a haptic tap and audio notification.
    - If Claude Code requires screen access, the app explicitly states this.
    - While listening, a level meter displays microphone activity, and transcribed text remains on screen for six seconds after being sent.
    - Long transcript entries fold after twelve lines with a "More" option.
    - A "Connection…" sheet displays the link state and raw error, allows for an immediate retry, and enables changing the Mac's address or port without requiring a new pairing.
    - The app curtain, shown when the app is in the background, displays the app icon and link state.
    - If a pairing key cannot be saved to the phone's Keychain, the app displays the specific Keychain error instead of remaining silently unpaired.
- Connection handling: the phone no longer waits for a 15-second timeout when the Mac is unreachable. Previously, `Network.framework` would remain in a "waiting" state on a refused or unreachable address until the network changed; the transport now fails immediately with the specific error (connection refused, no route, or timed out), allowing the reconnect loop's delays to take over. In simulator testing, the failure reason appeared within four seconds when the host was stopped.
- When a Mac removes a phone's pairing or has never known it (such as after a reset), the phone previously saw only a closed connection. This caused the phone to retry every 15 seconds indefinitely with the error "Can't reach your Mac." The Mac now sends a specific refusal (indicating the device is not paired, has been removed, or is using a different protocol version) before closing the connection. Upon receiving this refusal, the phone stops retrying and displays "Your Mac no longer knows this phone" along with a "Forget this Mac and pair again" button. The phone will only attempt to reconnect once more when the app returns to the foreground. This change does not disclose sensitive information: device IDs remain randomized, and an incorrect key still appears as a dropped connection. This behavior was verified in the simulator against a host that had forgotten the phone.
- The phone app automatically reconnects when it returns to the foreground, when the network state changes (Tailscale reconnecting or switching from Wi-Fi to cellular), or when a ping fails. When the app is suspended on iOS, the connection freezes. Previously, the phone waited up to 35 seconds for a keep-alive timeout and an additional 15 seconds to retry. The current implementation checks the link immediately upon returning to the foreground. If the Mac has been inactive for over 15 seconds, the app replaces the link at once. The retry interval doubles from 1 second up to 15 seconds between failed attempts. In simulator testing, the app reconnected 0.4 seconds after being brought to the front. The reconnection logic is handled by the `Reconnector` loop in `PairVoxLinkKit`, which includes associated tests.
- Replies start about a second sooner. Measured on the real voice: Kokoro puts about 0.4 s of silence before and 0.5 s after every sentence ("Okay." is 1.45 s of audio, 0.48 s of it speech). That delayed the first sound, left almost a second of dead air between sentences and made the "On it." acknowledgement hold the speaker for 1.3 s while the real answer waited behind it. The silence is now trimmed (30 ms kept before, 170 ms after, with a short fade), and Settings, Voice has "Tighten pauses between sentences" to turn it off. A replay of one turn on the real engine and speaker, with Claude's first token at 1.0 s, put the answer's first sound at 2.35 s before and 1.30 s now.
- An acknowledgement or a line of tool narration that is still waiting is dropped when the answer is ready, and narration that waited over 2.5 s is skipped instead of being spoken late. One that is already being spoken finishes.
- Tools: `PairVox --tts-probe "Okay.|Another sentence."` measures the installed voice (length, silence at both ends, synthesis time, length after trimming) without a window or sound; `scripts/claude-latency-probe.py` times how long a Claude session takes to start answering, the way PairVox runs it (it makes real, tiny Claude calls).
- The phone link now notices a connection that dies silently (Tailscale dropping, a phone out of range). Phones ping every 10 s and close the link if nothing arrives for 35 s, so the app reconnects instead of showing "connected" for hours. The Mac re-sends its latest state while idle and drops a phone that pinged and then went quiet. Older phone apps that never ping are not cut off.
- A phone that stops reading can no longer stall the Mac. Each phone has its own outbox: a newer snapshot replaces an older queued one, and a phone that cannot take data for 10 s is dropped. Before, one such phone blocked updates to every phone and left the caller waiting forever (found by the new soak test).
- Soak and fault tests: a mixed-conversation engine soak (`PAIRVOX_SOAK_SECONDS`, default 8), link connection churn with hostile clients, a snapshot storm with a phone that never reads, and a real stand-in host process that is frozen, resumed and killed while a phone is connected.
- Echo no longer counts as you talking. The voice detector now knows how loud PairVox's own voice has been and learns how loudly the microphone hears it, so the echo of its own speech is ignored (with no echo cancellation, this caused a false barge-in every couple of seconds in a replay of the mic-test conditions). You can still talk over it: your voice has to be roughly 10 dB above the echo. Echo that is recognised as echo also no longer raises the detector's noise floor.
- A replay harness for the voice path: synthetic or recorded microphone audio goes through the real detector and engine with a simulated speaker that leaks into the microphone. Scenarios cover a clean command, echo at five levels, talking over the agent, noise bursts and a slow rise in the noise floor.
- The "Pair this phone?" question is a regular window instead of a modal alert. The modal alert froze the whole app (phone link, command-line control, interface) until someone clicked. A newer request replaces one nobody answered, and an unanswered window withdraws itself after 150 seconds.
- A pairing code created with `pairvox-link` now expires on screen like one created in Settings.
- `pairvox-link-testhost`: a stand-in for the Mac side that auto-accepts pairing, for testing the phone app in the simulator. It is not part of the app.
- New app icon: an orange prompt chevron and three voice bars on near-black, flat colors, replacing the purple gradient. Eleven concepts and the generator are in `docs/icon-concepts/`; `scripts/make-app-icon.sh` turns any of them into the app's icon set.
- Talking over PairVox no longer makes it repeat itself. Speech now pauses in place when you start talking. If what you said turns out to be nothing (a cough, noise, an echo of its own voice) it carries on from the exact spot instead of discarding the sentence and reading it again. A bare "okay" does the same. Anything you mean for PairVox still stops it, as before. A stuck transcription cannot leave it paused: speech resumes after 12 seconds.
- While speech is paused, no new sentence is synthesized, so the transcriber has the GPU to itself. In the mic test, one decode took 4.8 s while speech was queued behind it.
- Long replies are read in part. After 15 sentences (Settings, Speech, Long replies: read everything, 10, 15 or 25) the rest is held and PairVox says "That's the first part. Say details to hear the rest." The full text stays on screen.

- Pairing: the phone now waits up to 130 seconds (it gave up after 15, before you could click Pair on the Mac) and shows that it is waiting. The phone confirms that it received its key; a Mac that gets no confirmation removes the phone again, so a failed attempt no longer leaves a phone on the list. The phone app must be updated together with the Mac app.

- Development builds no longer ask for Keychain access after every rebuild: phone keys live in a private file in builds without a team identity, and in the Keychain in signed builds. The app no longer reads the Keychain at launch, and the key store is read off the main thread.
- Screech recording: when the microphone hears a loud single tone while PairVox is speaking, the last ten seconds of microphone and playback audio are saved to the log folder (private files, newest ten kept, switch in Settings, Logs).
- New tools: `scripts/restart-app.sh` (swap in the last build and reopen), `pairvox-link doctor` (checks Tailscale, the forward and the link), and `docs/DEV_ENVIRONMENT.md` (notes on this Mac's build and signing quirks).

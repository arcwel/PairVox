# Strix gate for v0.1 (2026-10-24)

Strix 1.7.0 ran on `gemini/gemini-3.5-flash`, a model from a different family than the one that wrote the code. It ran inside its Docker sandbox (OrbStack). The target was a copy of branch `fix/v0.1-security-gate`: commit `fbcd1ed` plus the audit run 6 fixes, with all 482 tests passing.

## Result

**Passed: no finding at any severity.** Run `pairvox-fix_dcae`, standard mode, $1.57 spent against a $6 cap, with no custom brief. Strix ran a white-box review using Semgrep, Gitleaks, TruffleHog, Trivy and ast-grep. It recorded six coverage areas, each with "no issue identified" or "ruled out":

1. Voice and speech injection into the permission policy (`PermissionPolicy.swift`).
2. Environment variable injection and credential leakage (`ChildEnvironment.swift`).
3. Phone link pairing and frame encryption (`LinkCrypto.swift`, `Pairing.swift`).
4. Credential storage in the Keychain (`KeychainStore.swift`).
5. Secrets in diagnostic logs (`LogRedactor.swift`).
6. `file://` and SSRF in `scripts/pin-whisper-models.py`.

The report and SARIF are in `strix_runs/pairvox-fix_dcae/`; the console output is in `2026-10-24-v0.1-gate-3.log`.

## What did not run, and why

- **The live attack on the phone link did not happen.** The first two attempts targeted the source and `pairvox-link-testhost` (the real `LinkHost` and `PairingManager`, loopback only, reachable from the sandbox at `host.docker.internal:47822`). Both came with a written brief. Gemini refused both before running any tool, citing its safety policies, so neither counts as a pass. Their reports are kept as `strix_runs/pairvox-fix_c06d/` (source plus host, with the brief) and `strix_runs/pairvox-fix_862b/` (source only, with the brief). Only the third attempt, with no brief and no network target, ran. The pre-auth frame parser therefore has unit tests (`LinkTests`, `LinkSoakTests`) but no fuzzing or live attack; that gap is backlog 3.10.
- **The macOS app cannot run inside Strix's Linux sandbox.** Everything except the link host has to be reviewed from source.

## Tooling notes

- `~/.agents/skills/strix-qa/run.sh` passes `--run-name`, which Strix 1.7.0 no longer accepts, so `run.sh scan` fails at once with exit code 2. Strix now names the run itself under `./strix_runs/`.
- The skill says Docker comes from Colima. On this Mac it comes from OrbStack, and the scan works as-is.

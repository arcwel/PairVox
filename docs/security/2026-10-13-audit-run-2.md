# Security audit run 2: v0.2b (2026-10-13)

Second full audit of PairVox, scoped to what changed since the first (folder grants, several projects, advisor, spoken confirmation, mini window). Profile: standard, scoped. Source: commit 9d21c7f plus the uncommitted v0.2b work. The first audit is `2026-10-13-phase1-hardening.md`; its follow-ups are in `2026-10-13-remediation.md`.

## How it ran

Target code was executed only in a macOS `sandbox-exec` profile: no network, empty environment, scratch-only writes, unreadable home folder, CPU/memory/file limits. Only the Core library, the CLI and the Core tests build under that sandbox. The Voice and App targets, the scripts and the GitHub workflows were read as source and exercised by copying one self-contained function into a Core test where possible. The Claude CLI and every model call were off limits. Each candidate went to a separate verifier that had to reproduce the result itself.

Twelve hunter and reconnaissance agents produced 20 candidates. Each was verified by a separate agent: 13 are confirmed, 6 need a fact the sandbox cannot observe, and 1 was refuted.

## Confirmed and fixed

Every row has a regression test in `Tests/PairVoxCoreTests/SecurityHardeningTests.swift` unless noted.

| Finding | Severity | Fix |
|---|---|---|
| A shell folder grant covers `cd` with no target, brace expansion (`{~,x}/.zshenv`), `nc`, and quoted or backslashed `..` (`.\./x`, `.''./x`) | Medium | `shellGrant` refuses `{ } [ ] !`, backslashes, quote-adjacent dots, `>(`, `=(`, heredocs; `cd` must have one plain target inside the folder; `..` never counts as inside; option-attached paths (`-C/etc`) and URLs are resolved; `nc`, `telnet`, `ftp`, `git remote`, `gh`, `docker`, force and recursive deletes join the disqualifiers |
| High-risk shell commands rated medium when spelled differently (`rm --recursive`, `git -p push`, `/usr/bin/sudo`, `\| /bin/sh`, `chmod --recursive`, `docker container rm`) | Medium | `BashRisk` now also classifies by program and subcommand: basename of the program, git global options skipped, long flags treated as short, pipe-to-interpreter after a downloader |
| Spoken approval prompt names only the first three words of a compound command | Medium | The prompt lists every step; a command with more than three steps, substitution, redirection or a network reason is screen-only |
| Auto-approved read-only tools could read `~/.ssh`, `~/.aws`, `gh` and Docker credentials, or any file outside the project | Medium | Sensitive folders match without a trailing slash and include `~/.config/gh`, `~/.docker`, Keychains, `~/.claude` and PairVox's own settings; reads outside the project, including an absolute Glob pattern, ask first |
| An edit grant on a folder containing PairVox's settings let a steered model rewrite the consent store | Medium | The settings folder and `~/.claude` are sensitive (writes are high risk, never grant-covered); no grant is offered for `/`, the home folder or a folder holding them; a settings file that is not private to the user loses all standing consent on load, not only the Claude path |
| Catch-up open: a casual "okay" approved a request or a folder offer that had never been announced | Low | Approval words do nothing while the catch-up question is open |
| Spoken refusals with contractions ("I wouldn't allow that", "can't confirm high risk") and "ask again" parsed as approvals | Low | Any `n't` word, "cannot", "decline", "refuse", "wait" and "hold" refuse; "ask again" no longer means always allow |
| Folder-grant answers could be satisfied by fragments of PairVox's own prompt ("say yes", "yes again to allow") | Low | First step takes a one- or two-word answer that does not start with "say"; the second step needs the word "confirm" |
| Advisor text, written by a model that read the request, could contain "Allow." or "Confirm high risk." and be read aloud | Low | Sentences that would parse as an approval are dropped before the advice is spoken (`AdviceSpeechTests`) |
| `pairvox-cli` printed utterance text and the sign-in problem with control bytes | Low | `Term.format` and the auth line sanitize at the print site (CLI is an executable target; checked by building) |
| The Whisper pin generator wrote remote strings into Swift source unescaped, and the model store followed `../` paths | Low | Generator validates paths, commits and digests and exits on anything unexpected; the store refuses absolute, empty, `.` and `..` components (`WhisperDestinationTests`) |
| Exported diagnostics and logs named project and client folders (`folderGrants`, `declinedGrantFolders`, `openProjects`), and JSON escaping hid the home path from the redactor | Low | One shared key list used by the exporter and the settings logger; the export no longer escapes slashes |
| Menu-bar, mini-window and "Allow together" could approve text that was cut off | Low (not run: SwiftUI) | `fitsCompactSurface` (one short line, at most one reason, below high risk) gates those buttons; the rest say "Review"; Cmd+Return no longer answers a high-risk card |

## Refuted

The claim that `xcodebuild` ignores the committed `Package.resolved` was measured false in the first audit and again here.

## Hardening notes not acted on

Zip and logs are created with default permissions inside user-only folders; the export lands on the Desktop (iCloud may sync it); `removeAPIKey` does not restart running children; `saveAPIKey` deletes before it adds; `stderrTail` is logged regardless of the conversation-text setting; a project switch leaves holdSpeech state; closing a project leaves its handlers installed. None crosses a boundary on its own.

## Limits of this audit

This run is marked incomplete. The post-wave-2 coverage critic found three surfaces and one blocked unit that no hunter reviewed, and no further hunter wave or final-clean critic pass was run.

| Gap the critic named | What was done |
|---|---|
| Advisor prompt fence and subprocess (unit was blocked) | Parent fixed the fence (markers broken inside request data; tool name, reasons and path moved inside it) with `AdvisorFenceTests`. Environment minimality and process cancellation were not reviewed |
| `pairvox-cli` `/approve`, `/deny` and `--raw-log` | Raw log is now created 0600. `/approve` still approves whatever is shown when typed and has no risk gate, because typed input is the only way to approve high risk in the CLI. Not independently reviewed |
| Repository names fed to the recognizer as prompt and context words (`Transcription.swift`, `RepoVocabulary`) | Not reviewed. A repository could bias transcription toward words such as "allow" |
| `VoiceCatalog.swift`, `Makefile` | Parent read both: no input reaches a command or path from them; `scripts/release.sh` now rejects anything that is not a version number |

Core-only execution; Voice, App, scripts and workflows were read as source. Fixes to the App views (compact approval surfaces, Cmd+Return) were built but not exercised on screen. The four advisory-only memory and egress items in "Hardening notes" were left as they are.

The run's working files (machine-readable findings, coverage ledger, agent scratch) were removed on 2026-10-17; this report is the record.

# PairVox 0.1.0-beta.2

The second beta of PairVox, a voice front-end for Claude Code on the Mac with a companion iPhone app. This build stops listening to an empty room and closes a way for room speech to grant folder access. It also brings the release tooling and re-recorded demos.

Three of the five v0.1 checks have still not been measured (a timed headset session, spoken approvals on the Mac, and saying "Allow" on the phone), so it stays a beta.

## What's new

**The microphone goes to sleep.** After 3 minutes without conversation, the hands-free microphone mutes itself. The top bar turns orange and shows "Microphone asleep · Wake", and the microphone button becomes a moon. Click Wake or press ⌃⌥M to turn it back on. A sleeping microphone records when you hold the push-to-talk key, and stops when you let go. Claude thinking, working or speaking in any project counts as conversation, and so does anything you send. Noise that never becomes a message doesn't, and the microphone never sleeps while you're talking. Settings, General, Listening sets the time (3, 5, 10 or 30 minutes) or turns it off.

**Folder access takes a click.** The offer to let Claude edit every file in a project folder, or run commands there, no longer accepts a spoken or typed yes. PairVox answers "Folder access needs a click", and a spoken no still declines. With "Allow confirming high-risk requests by voice" turned on, you can still grant it by saying yes and then confirm. Each answer must start after its question began playing, must not be PairVox's own words heard back, and must come within five minutes. Touch ID is also asked for when that option is on. This came from a test on 2026-10-25, in which a hands-free session in a room full of conversation ended with a folder grant.

**Release tooling.** `scripts/release-assets.sh VERSION` builds every file a release carries (DMG, unsigned `.ipa`, Strix report, security-report zip and `SHA256SUMS`) and prints the `gh release create` line. It accepts `--dry-run` and `--json`, and never uploads anything itself.

**Demos.** The README's Mac demo was re-recorded in a neutral folder. It shows a typed request, a "no, do this instead" redirect, an edit approval and the fix. The README also has a still of the sleeping microphone.

## Install

**Mac.** Download `PairVox-0.1.0-beta.2.dmg` and drag PairVox to Applications. It is ad-hoc signed and not notarized, so macOS blocks the first launch. Open it once, then go to System Settings, Privacy & Security, click **Open Anyway** next to PairVox, and open it again. You need macOS 15 or later on Apple Silicon, and Claude Code installed and signed in (`claude`, then `/login`).

**iPhone.** `PairVoxPhone-0.1.0-beta.2-unsigned.ipa` is not signed. Install it with AltStore or Sideloadly, which sign it with your own Apple ID, or build it from source (see `ios/README.md`). With a free Apple ID the app opens for 7 days before it needs reinstalling. You need iOS 18 or later and Tailscale on both devices.

## Security

Code audit run 9 covered everything changed since run 8, including run 8's own fixes. It found six leads, all fixed in this build with regression tests:

- **The downloaded Mac app can no longer be debugged by other programs.** The beta.1 DMG let any process of the same user attach a debugger to PairVox, which could then read the API key and phone keys from memory or borrow its microphone permission. This build runs with the hardened runtime and without the debug entitlement. If you installed beta.1, replace it with this build.
- **Spoken answers are timed by their own start.** Before, a second utterance or a short blip could leave a "yes" untimed, and an untimed answer skipped the before-the-question and own-voice checks.
- **The second "allow all" counts only after the list it confirms has started playing**, and allows only requests still fresh.
- **More ways of printing the environment are high risk** (`nice env`, `ps -ax -E`), so a folder shell grant never covers them.
- **The lock-screen Allow needs a request on one plain line.**
- **Muting clears the short lead-in buffer.** Push-to-talk after a mute sends nothing heard while muted.

Strix found nothing on the release code, though it recorded only part of it (see its report). A Gitleaks scan of the full history found no secrets.

`PairVox-0.1.0-beta.2-strix-report.md` is the Strix report. `PairVox-0.1.0-beta.2-security-reports.zip` holds the full Strix output and the run 9 audit report with its findings. Both are also in the repository under `docs/security/`.

## Known limits

- The Mac build is not notarized, and the iPhone build is not signed. Both need a paid Apple Developer account.
- The phone link has not been fuzzed or attacked live.
- The phone's Face ID claim is reported by the phone itself, so a modified phone could approve what an unmodified one could approve with a tap.
- Downloaded builds have no in-app updates yet.
